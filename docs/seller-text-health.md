# Seller text protection and number monitoring

Approved November 1, 2026 after repeated cold introductions reached the same person through different property records and business numbers. A sender being enabled or a provider accepting an outgoing message does not verify incoming service.

Cold seller SMS now permits one introduction per recipient, across all account/property/number history. One unanswered reminder may follow 3–5 days after the original dispatch, on the same thread, only while existing contact evidence remains valid. After that window or a second attempted message, unanswered automated outreach pauses. Retired history, reserved sends and uncertain outcomes still count; changing property or number cannot reset the sequence. Existing requested-contact sequences, manually authored replies and source-backed negotiations retain their original admission rules. A soft refusal about a different property blocks more cold outreach but does not itself stop an active conversation or signed deal; their original property controls still apply. Global stop-contact suppression continues to block every send. No consent, contact check, balance, provider receipt or eligibility date is renewed.

The scheduler checks the same guard before selecting new/recovery work. Final text admission checks it again under the existing budget and recipient locks, before reservation and at operation claim. The original account, sender, suppression, hours, funding, Pause and unknown-outcome gates still apply. Reply processing already precedes new introductions in the root scheduler and remains in that order.

New introductions name the actual saved buyer company (or principal), identify the exact street and ask the existing ownership question. At the owner's November 3 Central / November 4 UTC instruction, new `identity-v4` copy omits the added opt-out footer. The message must fit the existing one-segment character policy; unsupported identities/addresses hold for review. Its separate assignment context keeps revised-copy results distinct from `identity-v3` and earlier experiments. Incoming opt-outs and versioned intake consent remain unchanged.

The forward migration `20261104034309_seller_opener_footer_free_copy.sql` updates only exact automatic v3 ownership questions still ready with no provider, event, delivery, operation or conversation evidence. Each message and its matching assignment move together under the existing scheduler/budget locks. Only expired unconsumed tickets or completed pre-admission budget holds are eligible; active, consumed, reconciliation-held and other uncertain work retain their original copy and controls. Sent history, customer-authored messages, campaigns, incoming messages, source evidence, prices and routes are never rewritten. Original creation, delivery and ticket timestamps are preserved; eligible copy updates advance the message's `updated_at`. Run `node --experimental-strip-types tests/seller-opener-footer-free.test.mjs` for the new copy and preservation cases; older migration tests deliberately retain their historical copy assertions.

Natural stop-contact requests such as “Stop asking me” and a final “Stop.” suppress contact. Repeated refusals such as “I have told yall NO” pause automation. Quoted/negated speech, “stop by tomorrow” and price negotiations retain their existing interpretation. SQL, webhook normalization, text analysis and call results share the same tested source-word policy. Never infer carrier complaints from opt-out counts.

The owner-only admin overview refreshes each line's original receipts: today's property texts and customer updates, 24-hour property acceptance/delivery/review counts, incoming people, confirmed selling interest, opt-outs, refusals, complaint wording, carrier blocking notices and last saved non-carrier incoming message. Duplicate inbox/property representations count once. Carrier complaint totals remain explicitly unavailable. A missing incoming message is unverified service, not a confirmed outage; a saved message is an observation, not a guarantee of full carrier health. The dashboard never probes by sending a paid text.
