# Property text reception evidence

The November 4 audit found delivered property outreach without recent saved property replies. Generic lifecycle inbox receipts were still arriving. The previous health query combined these sources, allowing an unrelated unknown/customer/webinar reply to clear the warning for property reception. Lack of replies is an unverified path, not proof of carrier failure or lost messages.

The forward migration keeps the original all-incoming counts and adds separately account/thread-bound property reply counts and last observation time. It never guesses a route from a phone/time match or processes historical inbox content. Only a real received property message with a provider/event receipt can demonstrate the property path; carrier notices and verification-code wording cannot. Generic duplicate event receipts do not count twice. Enabled lines with recent accepted property outreach and no current routed reply remain in the existing reliability warning, independently of healthy worker checks.

Authenticated webhook rejection/processing failures now increment private hourly counters with fixed categories and stages. Incoming schema rejection is distinguished from other/unknown event types without retaining raw payload, phone, message, event ID or credentials. Authentication failure does not write diagnostics. Monitoring uses an independent one-second deadline and keeps the existing failure response if recording fails; a fixed log is retained as fallback. Counters count HTTP attempts, including provider retries, not unique lost messages. Their window includes the current hour and preceding 23 hourly buckets, and the UI displays the exact window and monitoring installation time. Zero recorded failures is not proof of complete receipt coverage.

Operator health shows both paths, observed failures and the evidence limitation. Customer status, sending/STOP rules, original messages, routes, permissions, prices and unknown receipts do not change. Missing or failed monitoring preserves previous evidence and existing independent workflow incidents.
