# Buyer search continuation

Shared buyer discovery previously remembered only its last page. When the first search still had more results and the second search was exhausted, it stopped both searches. In particular, an account assigned corporate owners first could receive one broad page followed by an empty recent-corporate page and never read the next broad page.

The service now reads the complete bounded receipt history for the same deal and configuration revision. Each reviewed strategy retains its own provider-page cursor. The existing second-strategy order remains preferred; once it ends, the first strategy can continue only when its own last saved receipt explicitly reports another page. Global pages, provider pages, original operation keys, pricing, the exact property ZIP, corporate-owner targeting, current admission checks and the total five-page maximum remain unchanged. Unlabelled legacy history keeps its original behavior rather than receiving invented shared-learning assignments.

The matching database predicate is still a private, stable, security-invoker read. No admission or receipt-save locks change. Original receipts are never rewritten. Paid/uncertain operations remain held under their original operation key; a new cursor cannot retry them. Current learning-safety holds still stop before requests.

Apply `buyer_search_independent_cursors` before releasing the new service. The migration requires the exact original predicate body and preserves private ACLs. A service read also validates its proposed cursor against the installed database before any provider request, so an older database safely declines the new continuation during deployment overlap. The existing final claim and receipt-save checks remain authoritative; this read is not a financial authorization.

`tests/buyer-search-cursors.test.mjs` reproduces the old TypeScript and SQL failure, checks all 62 complete five-page histories across both strategy orders, verifies SQL/application parity, rejects malformed/cross-account cursors, and exercises the actual service with simulated provider responses and real empty/paid receipt-saving SQL. It also checks immutable prior receipts, idempotent saves, mixed-deployment holds, unchanged learning holds, final claim rejection and no retry after an uncertain provider response. No provider tests are used. This change does not add geographic expansion, individual-owner targeting or a higher purchase allowance.
