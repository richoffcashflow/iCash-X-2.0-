# Pending confirmation and current activity

A `pending_work` observation identifies an unresolved original operation. It can
coexist with current independent work, so it does not by itself prove every task
is blocked. The activity reader now retains `pendingConfirmation` alongside a
valid consumed ticket or running screening lease. Expired, issued and finished
work still cannot produce an active task.

The owner account preview shows the actual current task and the earlier-work
confirmation note together. Without current task evidence, it shows “Awaiting
confirmation” with no live indicator or animation. The customer workspace keeps
its saved Run/Pause presentation and existing task labels. Actual Pause, missing
completion, configuration blocks, unavailable reads, stale data and account-view
isolation retain their existing precedence.

This presentation change does not clear monitoring findings, settle costs,
release money, retry work or claim account recovery. Backend health observations
and all original financial and provider evidence remain unchanged.

Offline activity, component and owner-route checks cover active and idle pending
work, expired evidence, true blocking observations, customer Pause, stale reads
and principal isolation. Canonical exact-release checks and normal deployment
verification remain required.
