# Account-bound incoming-lead priority

The hybrid research scheduler treated a demo already assigned exclusively to
another customer as available incoming inventory. Its older three-customer count
also ignored the demo's one-customer limit. Funded accounts with a saved nationwide
profile could consequently remain idle without ever buying a research page.

Research now defers only when the incoming candidate passes the same source and
customer binding checks used by assignment: the demo's account and one-customer
limit, direct-principal exclusion, and the existing Meta pool receipt and match.
The source must also have current enabled processing and data rights. Actual
assignment still performs its original locked checks. This migration never
reassigns a seller, copies another customer's conversation, or spends credits.

This corrects the shared scheduler for existing and future accounts. Verified
prepaid purchases already activate funded spending; enabled accounts retain their
existing pacing, prospecting allowance, protected outreach capacity and wallet
history. Manual Pause and final provider/recipient admission remain effective.

The local database regression starts with the actual deployed search predicate,
reproduces the assigned-demo stall, applies the migration, and verifies genuine
available intake still gets priority. It also checks source isolation, disabled
processing, expired rights, opt-outs, affordability, Pause and zero balance.
