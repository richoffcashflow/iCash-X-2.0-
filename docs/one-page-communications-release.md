# One-page communications and closing progress

The workspace starts with three prioritized properties. Up to six are fetched per page; one deal opens at a time. Text, email, call details, document controls, buyer progress, title replies and closing milestones remain in the existing page. Hidden deal panels preserve in-memory drafts during this page session using React Activity and suspend their effects. Navigating property pages or reloading does not persist unsent drafts. No promise of autosaved drafts is made.

Dashboard refreshes omit call transcripts and document HTML. Call transcripts load in 60-turn batches; text and email histories in 20-message batches. SMS contacts use 20-contact batches. Message histories have bounded scroll areas. Polling stops in hidden tabs and closed panels; dashboard reprioritization pauses while a property is open so active work does not jump around. Independent database reads run in parallel; message history indexes include the tenant and cursor columns. Property-list pagination still uses the existing priority query and offset; 100,000 monthly users or simultaneous sessions have not been load-tested. Do not represent this release as a capacity certification. Load-test realistic active users, database lock contention (especially the shared operation-budget lock), provider concurrency and webhook throughput before expanding traffic substantially.

Manual texts reuse the existing authenticated send endpoint, contact permissions, local hours, opt-out suppression, provider claims and reservations. Taking over a property stops its new automatic replies; already-dispatched work may finish. Global bot pause also holds manual sends under the existing spend policy. No call or text was sent in this release's verification.

Manual email is a transaction mailbox. Recipients are resolved server-side from the current verified title contact and counterparties on completed non-test purchase/assignment envelopes. Customer signers are excluded. Signed-party contact validity lasts 90 days after the recorded envelope update; title uses its existing expiry. This is not an arbitrary-address marketing sender or a full hosted inbox. The displayed sender uses the customer's principal through the configured iCash X email domain; customers do not connect their own mail provider. Known-contact emails can be composed, sent, read and replied to inside the deal. The UI displays the configured charge before sending; the new manual_email rate copies the existing documented title-email cost/overhead baseline and expiry. Rate IDs are pinned to each send. No automatic pricing change or margin relaxation is introduced.

Outbound email claims are atomic with credit and operating-cost reservations, idempotent and bounded to five newly queued messages per deal per minute. Provider errors and unknown outcomes are held for reconciliation, not automatically resent. Provider acceptance is labelled acceptance, never confirmed delivery. Actual cost settlement remains the existing separate reconciliation process.

The existing signed receiving webhook supports ICX-M references. Incoming email must match the configured inbox, a single message reference, the expected counterparty and DMARC pass before appearing in a customer's account. Unverified mail is not exposed. Current title-contact replies also enter the title evidence flow when a matching title request exists. Attachments and arbitrary HTML from received mail are not rendered. Existing title T/Q handling remains intact.

Closing updates require an authenticated account owner, completed non-test purchase signatures, and a reviewed authenticated reply from the current verified closer. Deposit and closed milestones additionally require completed non-test buyer signatures. A contract deposit must be confirmed before closing; future dates cannot be recorded as completed closings. Replays are idempotent and conflicting edits are rejected. Updates do not assert that money has been paid to the customer. No deposits, wires or closing funds are moved by this code.

Fulfillment attempts the existing title-opening flow only if automatic coordination is enabled and a verified title contact exists. Existing signed-agreement, pause, permission and cost gates still apply. An accepted email requests opening; it never marks title open or the deal closed by itself. Missing title contacts continue to require setup.

Setup now shows the actually saved voice, market and included tools as a compact checklist, and removes the requested footer FAQ and extra reassurance line. There is no simulated operational progress or invented property outcome.

Validation: TypeScript; focused email/header/idempotency/timeout, title webhook, closing input, SMS payload, setup and fulfillment tests; a rollback-only database test covering cross-tenant rejection, test-signature rejection, milestone evidence, deposit/future-date checks, mailbox contacts, conflict replay and inbound verification. Fixture rows were rolled back. New tables enable RLS and expose no direct anon/authenticated grants. Security advisor retained the existing leaked-password-protection warning; the service-only RLS/no-policy findings are expected.

Incoming voice is not completed by this release. The public 424 number's forwarding destination must be verified in Contiguity/Twilio, a production agent configured, and tenant-safe inbound context routing connected. At release preparation there were zero production voice configuration rows and Twilio required sign-in. A shared inbound number must never default to a customer's private deal when the caller matches multiple accounts; caller ID alone is not authentication. Do not claim the shared number is live until that path is verified.
