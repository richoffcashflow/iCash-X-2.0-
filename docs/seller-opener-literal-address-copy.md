# Literal seller copy and contact-proof ordering

A read-only review on November 3 found 95 fresh opener candidates in the earlier
unbounded invitation/opener selector, before the existing 32-row cursor. All 95
were within current dispatch hours; 70 passed the current cadence check and
none had a ready saved invitation. The bounded first page contained 32 threads:
21 passed cadence, seven had an old sending principal, and the other 14 had
copy rejected by a restricted character expression.

The rejected messages were 111–118 characters. Ten used a saved company name
containing an ASCII hyphen, three contained a unit marker `#` (one also a
hyphen), and one contained a fractional-address slash. The existing financial
single-segment validator and application GSM counter already accept these
three basic characters as one unit each. They were rejected by the narrower
opener helper/queue expressions, just as the earlier literal ampersand case was.

The correction permits exactly `#`, `/` and `-` at the five matching checks
in four existing functions. It does not normalize, shorten or invent a principal
or address, accept arbitrary Unicode/markup/newlines, increase the 160-unit cap,
change the saved rate or send a provider request. All original consent, active
phone, DNC, source, hours, funds and queue controls remain in force.

The candidate helper also builds the existing copy before its full contact
review. An impossible string can return NULL without acquiring the expensive
proof locks. Every non-null candidate still requires the same
`icash_sms_thread_review_current(account,thread,false)` result to be exactly
true. Negative and unknown results remain rejected. The queue independently
reconstructs and reviews current copy under its original locks; a candidate
string is never dispatch authority. Existing selector order, invitation
semantics, bounded cursor and financial receipts remain unchanged.

This addresses concrete blocked valid work and unnecessary contact checks; it
does not establish that all cumulative dispatcher timeouts are resolved.
Read-only measurement of the 32-row cheap selection, hours and cadence cost
225.826 ms. A separate fixed-batch query performed 21 matching manifest checks
in 95.733 ms including cadence; the manifest portion added approximately
28 ms. Those measurements did not justify an unrelated manifest index.
Full contact review takes locks and was not executed by the read-only diagnostic.

The migration guards each complete installed function hash and changes only the
five character classes and the candidate helper's review ordering. PGlite loads
the real captured queues, routing and price/observer triggers. It covers the
original failure, literal character combinations, 160/161 boundaries, unsupported
characters, impossible-copy proof bypass, mandatory positive final review, actual
saved body/price/routing, duplicate prevention, customer controls and unchanged
unknown receipts and money. The final source-review boundary is synthetic in
the fixture and is labeled as such.

Native PostgreSQL adds 24 concurrent actual queue calls, unchanged budget-lock
races with source/expiry/Pause changes, concurrent identity/source changes during
the final candidate proof, real queue refusal after those changes, and current
identity reconstruction after an earlier preview. It contains no provider call
or customer-wallet debit. Require native CI and exact web/worker verification;
no production migration was applied while preparing this change.
