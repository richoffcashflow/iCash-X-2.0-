# Late evidence after unknown-export capacity recovery

The unknown-response recovery keeps the original export receipt absent and preserves its purchase, customer reservation, owner fence, held handler and request result. Its immutable source snapshot and three fresh free inventory responses establish a separate capacity decision, not a provider outcome or a customer charge.

A real original receipt arriving later must still save. The binding trigger accepts that later evidence while retaining the original verified review. The export and direct batch receipt writers acquire the same organization lock before their row locks; paid admission and capacity finalization use that ordering too. This serializes the late observation with new export admission without making an export-to-organization lock cycle.

If a late receipt remains nonterminal, an immutable private observation restores the global capacity block. Both capacity projections, final paid admission and the existing owner-export monitor recognize it. The reviewed export stays outside the original unique pending index, so a newer pending export cannot cause the late receipt to fail or disappear. Repeated identical receipt saves retain the first observation and never retry a provider request.

If the actual original receipt meets the existing terminal export rule, the late observation no longer blocks capacity. Original-ID receipt/download recovery continues separately; missing costs still retain the original financial reservation and owner fence. Terminal export capacity is not proof of settled money.

A contradictory late **nonterminal** receipt currently requires a separate fresh capacity reconciliation. The earlier idle decision does not automatically clear that later evidence. This release therefore repairs the verified current unknown-response stall and adds safe late-evidence handling; it does not establish universal recovery for every future provider outcome.

The focused disposable-database test loads the exact production writers and admission definitions. It covers a newer active export, late HTTP 500 and raw-null 504 responses, terminal HTTP 200, the independently callable batch writer, duplicate/lost-acknowledgement saves, unchanged money/review/owner restrictions, both capacity projections, monitoring and private privileges. Native tests separately verify concurrent lock behavior. No paid provider test is involved.
