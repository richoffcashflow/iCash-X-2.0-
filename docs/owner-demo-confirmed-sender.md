# Fresh owner demo sender preference

The November 10 owner request asks for the most confirmed numbers for their own demo. This extends `owner-demo-call-capable-routing.sql`, which already prevents fresh call-requested demo SMS threads from selecting an SMS-only lease.

Only the exact presenting owner account, owner actor, self phone, matched assigned intake and fresh five-minute call-request receipt qualify. Before any thread or call identity exists for that run, SMS and voice choose from enabled SMS and verified outbound-call-capable numbers using the same preference:

1. Signed, source-bound carrier-delay recovery first. An unresolved notice in the last hour outranks older success even after ordinary five-minute probe admission resumes. Only a verified later-dispatched delivery or notice expiry clears this preference penalty; normal sending eligibility is unchanged.
2. The latest source-verified cellular SMS/MMS reply from the preceding 24 hours. Match the original event ID, event type, account/thread, from/to phones, body and timestamp, including a retained raw provider alias when present. Ignore iMessage-only evidence, known service/system notices, stale/future/malformed receipts, unresolved routes, multiple active routes on the number pair, other roles and explicit test threads. Only current unpaused, automatic seller threads contribute. The original source time determines recency; re-ingestion does not refresh it. This is observed inbound transport, not a verified human identity or a delivery guarantee.
3. The smaller of the two recent confirmation counts, then their total. SMS requires a delivered provider ID and exact account/thread/actual dispatch. Recorded calls require an actual provider-started and ended session with its dispatched operation and matching registered provider/caller identity. These are transport observations, not evidence that a person answered or read a message, and not measured success rates.
4. The original deterministic hash for ties and when no recent evidence exists.

Inbound ranking verifies at most the newest 500 candidate messages per line in the 24-hour window. Per-thread indexed cursors use the existing active sender-pair and account/thread received-message indexes, with a 500-row per-thread cap before the final 500-row sample. If that sample lacks qualifying evidence, it earns no inbound preference; it does not scan older history to find a favorable result. The original provider receipt and message creation times must also be in the same 24-hour window. No customer message or recipient is returned.

Each outbound channel reads at most 500 eligible receipts per line from the preceding seven days before counting. Production provider/operation uniqueness prevents duplicate sampling without a full pre-limit distinct sort. The legacy primary number has no current outbound provider identity in the shared number registry, so its old calls earn no call-confirmation preference; its normal eligibility and deterministic fallback remain unchanged. Future, stale, missing-dispatch, mismatched-account and unfinished receipts do not count. No per-recipient personal data is returned. Ordinary accounts, non-self demos, expired requests, disabled voice choices, existing current-run threads and unknown calls retain their existing behavior. Disabled/conflicted/suppressed numbers remain ineligible regardless of evidence. A disabled line is never enabled by ranking.

The migration only adds private read-only evidence helpers, the existing completed-call index and a guarded selector update. The inbound extension adds no index or table writes. The canonical atomic owner-demo restart bundle is generated from this component; never install the component separately. It does not archive any run, send/replay outreach, change call-request expiry, alter billing, or update historical bindings. New-run lifecycle retirement is separate. Final call and SMS admission remains authoritative if readiness changes after selection.

Offline checks: `node --experimental-strip-types tests/owner-demo-confirmed-sender.test.mjs` applies the exact preceding number migrations and owner call-capable migration, then tests the new migration and actual selector, including executable source-forgery, timestamp, notice, alias, ambiguity, sample-bound, capability and continuity cases. No paid or live provider tests.
