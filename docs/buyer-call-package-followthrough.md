# Completed buyer-call package followthrough

This candidate connects a completed inbound buyer's explicit request for package information or photos to one SMS containing an existing published package link. Existing call history could record that request for review without sending the requested package. This is a prospective offline-proven gap; historical customer impact has not been established.

The feature installs **disabled**. No provider configuration, activation, historical replay, live contact or production mutation is part of this branch. Outbound buyer contact remains SMS/email; this adapter sends SMS only to the already bound buyer thread and never grants SMS permission from voice consent.

## Source and action boundaries

Reception maintenance already verifies the exact carrier/session/conversation identity and completed provider status. The new source normalizer retains every transcript position, speech text and original offset; it rejects missing buyer speech, invalid clocks, oversized sources and truncation. Tool-only agent positions may contain null speech. The database independently validates the session/account/phone/conversation/buyer binding, canonical completed call, full-source shape and chronology, and equality with the existing history projection. Requests use original speech time, not maintenance/ingestion time. Both conversation start and every speech offset must also fit the carrier start plus its original maximum duration; a delayed terminal receipt cannot extend that window. Owner quick tests and owner-test threads cannot qualify.

Only a whole-message package request recognized by the existing classifier qualifies. Later unsupported intent, withdrawal, another channel or a human request holds the action. A middle withdrawal in a long conversation remains effective. The new private source journal is immutable. A changed replay writes a separate immutable conflict record, including changes hidden in the middle of the display projection. That conflict permanently holds the original action; replaying the first payload cannot restore authority. An action owns one fixed request key, original message ID, package link, asking price, purchase envelope and body. It cannot replace or reset that original.

Final dispatch rechecks current sources and controls under the existing budget/recipient lock order, delegates the **entire unchanged existing SMS claim chain**, and rechecks against a fresh database snapshot. A failed final recheck raises inside a subtransaction, rolling back all inherited reservation and dispatch writes. After all inherited/helper locks, it locks the captured followup row and compares its full snapshot through commit; no helper or lower-order lock runs afterward. Newer original-time replies, later or overlapping calls, unresolved same-phone calls, Pause/manual control, STOP/suppression, buyer holds, signed-purchase authority, changed/revoked/reserved packages and financial/contact admission retain authority. A newer call may have been created earlier during setup, so call start/end clocks are checked as well as creation time. The indexed completed-call scan covers possible original speech within the canonical 60-second setup plus 600-second maximum duration; the carrier terminal receipt itself may arrive later; unresolved calls have a separate conservative check. A missing carrier terminal receipt remains unresolved even if setup or consent expired; the adapter never invents a terminal outcome, and its own request authority expires after 24 hours. Only an exact incoming SMS/MMS event ID/type/body/from/to with a positive timestamp within 30 days before ingestion and five seconds after it proves that a delayed reply is older. Missing or invalid event proof uses ingestion time and holds newer input.

The current package helper uses `icash_journey_allowed`, `icash_sms_thread_review_current` and `icash_buyer_package_data` as existing authorities. It does not create or reprice links, alter accepted terms, book access, sign contracts, infer cleared funds or manufacture a text AI job.

The scheduler independently admits at most two messages per maintenance invocation. Pre-provider holds retain the same ready/provider-null original with a 30-minute lease. Dispatching, failed, unknown or reviewed originals never replay. Accepted messages await delivery evidence without resending. A delivered message with its provider ID can mark only the exact original package-only `buyer_followup` as `reviewed`, using its immutable row ID, account/thread/session/kind, exact quote, absent viewing/title work and complete captured row snapshot. Manual changes, mixed work, newer requests and late/duplicate receipts cannot clear other work. Accepted/unknown/failed delivery remains unresolved. An accepted original still lacking delivery after the 24-hour source window enters review.

Capture also checks a completed source when legacy immutable display history rejects its changed replay, so visible changes cannot bypass the durable conflict hold. An explicitly supplied empty, malformed or fully filtered transcript is checked even when it yields no display-history rows; it cannot leave the old package request dispatchable. An omitted/null optional retained transcript is not a contradictory source and does not replace or revoke the earlier complete evidence. Capture-write failure is deferred until after original recording settlement; the existing reconciliation lease retries the source write. Recording cleanup, settled costs and other maintenance lanes remain independent. No transcript, phone, URL or provider response is added to operational logs.

## Installation and rollout prerequisites

Migration `20261116225947_buyer_call_package_followthrough.sql` is CLI-generated and byte-identical to its config. It has no embedded transaction boundary: the migration runner must commit schema/functions and its ledger together. Shared advisory transaction lock `726341927`, 3-second lock timeout and 15-second statement timeout precede prerequisite checks.

The observed predecessor definitions are:

| Function | Definition MD5 |
| --- | --- |
| `icash_claim_text(uuid,uuid,text)` | `a59a859edb0742485bddd04e49975d60` |
| `icash_buyer_request_action(text)` | `44916db06dbd021456247df4816cfd94` |
| `icash_save_buyer_inbound_history(uuid,text,jsonb)` | `aa8596d51b98a17a940d6daba615559d` |

Ownership and exact postgres/service-role ACLs are pinned too. The old final claim becomes `icash_claim_text_before_buyer_call_package` without changing its body. Private schema/table access is denied to public, anon, authenticated and service-role callers; only reviewed service RPCs expose bounded results. Unexpected predecessors, ACL drift, existing candidate schema or repeat installation fail closed.

The release coordinator must install the disabled migration atomically, verify its ledger and permissions, release the exact tested web/worker code, and then separately approve prospective activation. Activation must serialize on the operating-budget row and set a fresh `enabled_at` at activation time. It must never backdate a cutoff. Capture requires both session creation and call start after that cutoff; final dispatch rechecks the cutoff. The existing buyer-reply policy must also be enabled. The application lane additionally requires production plus the existing SMS/live-work release flag. Disabling the private feature stops new claims; it does not erase original messages or receipts.

Register `buyer-call-package-database` and `buyer-call-package-service` in the existing local release suite list. Both are automatically discovered by all-tests. Add the native fixture to the existing database-contention job after its isolated `pg` driver installation; no new job or timeout increase is needed:

```sh
BUYER_CALL_PACKAGE_NATIVE_TEST=1 ICASH_PG_MODULE=/path/to/isolated/node_modules/pg \
  node tests/buyer-call-package-native.mjs
```

It requires the existing disposable PostgreSQL 17 loopback service at port 55443 with fixed fixture credentials and creates/drops its own random database. Shared CI/release-list edits remain with the coordinator.

## Evidence and limits

Actual SQL fixtures cover full-source binding, middle withdrawal, prospective cutoff, original-message recovery, receipt exclusions, current package/control checks, private ACLs and atomic installation. Actual service tests cover complete-source normalization, bounded independent work and source-write failure after settlement. The maintenance body is also connected to the actual SQL source/action and final claim to prove empty/malformed/oversized replay blocks the original send, leaves the first source immutable and preserves settlement; missing optional retained data remains distinct. Native PostgreSQL tests cover competing installs/captures/claims, original one-use dispatch, newer reply/call/STOP/reservation races, accepted versus delivered, committed followup/package changes during a blocked text claim with full reservation rollback, final followup-lock serialization, durable middle-only source conflict, manual-edit/late/duplicate receipts and indexed call lookup. SMS tests load the real existing reply-time helper and verify that its zero or wrong-event-type result cannot become older-source authority here. Existing maintenance, receipt, sender and hours regressions are also run.

The transport and financial providers are explicit offline fixtures. The installed outer dispatch wrapper is exercised with a fixture final admission boundary; this is not a reconstruction of every downstream production policy wrapper or evidence of live delivery. The existing history writer is pinned and immutable-source gated; service-role callers cannot insert public followup rows directly. A captured source without a followup gets a fresh absence check, without adding a broad table lock. The old display-history projection and existing viewing/reservation/signing handlers are unchanged. Unsupported requests, unverifiable source clocks, sources over 1000 positions/256 KiB and real manual controls remain held rather than receiving a fabricated completion.
