# Outcome learning release

Implemented: private persisted cohort assignments and append-only evidence events, idempotent server recording, and deterministic cohort metrics. This is an observation/recommendation layer; provider event adapters, scheduled aggregation and automatic allocator promotion are not wired yet. No fabricated events or demo training, no contact dispatch, no policy auto-promotion.

A cohort fixes the account, opportunity, strategy version, market and channel before work. Metrics group by these dimensions and assignment month. This prevents continuous new arrivals from making old cohorts perpetually immature. Strategy attribution is observational; controlled holdouts are required before claiming improvement.

Response rate is distinct contacted opportunities with a verified response divided by distinct contacted opportunities. Connection rate is connected operation IDs divided by attempted operation IDs. Contract and closed-deal rates use distinct contacted opportunities. Costs are recorded provider microdollars (one dollar = one million units), never customer credit prices. Costs per qualified seller/contract/closing remain null when no outcome exists. Attempt billing completeness flags missing attempt receipts; this is not a guarantee that all infrastructure/data/closing costs have been reconciled. No provider expense should be treated as free because a receipt is missing.

The versioned launch recommendation policy requires 90-day maturity, 100 contacted opportunities, five contracts, three closings and all attempt receipts before a cohort is eligible for a controlled experiment. These are configurable conservative defaults, not statistical proof. Suggested changes are capped at 10%; an operator must compare comparable mature cohorts and reconcile ALL provider costs before approving a holdout test. Elevated opt-outs trigger review immediately without waiting for maturity. Existing daily pacing, reserves, consent/quiet-hour gates, pause and margin controls remain authoritative. Neither this module nor a model can increase a user's spending authorization.

Provider handlers must verify signatures, resolve tenant/deal/operation IDs from stored jobs, and then call recordLearningEvent. Never accept a client's tenant ID or an LLM success claim as evidence. Signed-document evidence is required for contracts, title confirmation for closed deals and billing receipts for costs. Duplicate receipts count once; conflicting replays fail. Test mode is excluded from learning. Raw conversations and personal contact details do not enter these tables.

Storage uses account/deal composite foreign keys, RLS with client grants revoked, and service-only inserts/reads. No updates or deletes are granted to the service role on these new tables; corrections require an audited reconciliation process before promotion. Existing private brain decision/provider-cost tables remain separate; connecting their verified receipts is part of the pending worker integration.

Verification: production build and TypeScript passed; tests cover duplicates, tenant separation, demo exclusion, future events, absent denominators, cost gaps, opt-out review and cohort separation. Transactional database test under service_role validated insertion, exact replay, conflicting replay rejection and unsigned-contract rejection, then rolled back all fixtures. Anonymous/authenticated access denied. Security advisor notes intentional service-only RLS without client policies; existing leaked-password protection warning remains unrelated to this passwordless change.

Next delivery: durable worker + provider webhook adapters, reconciled operation costs and one controlled end-to-end seller/buyer workflow. Real acquisition remains disabled until those pieces are verified.
