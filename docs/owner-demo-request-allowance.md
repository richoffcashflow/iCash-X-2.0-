# Owner demonstration request allowance

On November 3 the owner requested bypassing the exhausted research queue for
their own Test your bot submission. Previously saved owner examples were older
than the 24-hour research window. Reusing them as current would not make the
live call eligible, so this path admits one fresh address lookup instead.

The exception applies only to the exact existing owner account and its own
configured demonstration phone. The ordinary limiter runs first. Only an
explicit, fresh five-minute demo-form call request can use the exception, and
only when the unchanged shared rolling allowance is exactly 9,800/9,800.
An original admitted provider response must confirm the 10,000/day and 70/minute
provider limits. The existing 60/minute ceiling and provider cooldown remain.

One transaction locks the ordinary spending controls, owner account and wallet,
fresh intake/request and shared limiter; rechecks elapsed time; obtains the
normal lookup claim and spending reservation; and records one immutable
admission for that rolling day. It increments the actual shared counter to
9,801. It does not change the 9,800 limit, reset its window, consume the starter
reserve or grant another customer's work access to the exception.

The application uses that exact claim for one address-enrichment POST with no
alternate-format fallback. Provider response, 429 and unknown-outcome metadata
use the existing request ledger. A lost response, failed lookup or no-match
does not restore the exception. Ordinary research billing and fresh property
qualification still apply, followed by the existing call, text, seller
agreement and signature checks. No old contact request or property research is
renewed, and the installation itself does not submit a demo or send anything.
