# Independent property discovery

`ICASH_DISCOVERY_WORK_READY=true` admits the existing property-only discovery service and automation ticket while `ICASH_LIVE_WORK_READY` remains false. It defaults OFF. The independent path supports at most five property records per page, always `anchor: properties` and `contact_audience: none`, with the existing free estimate before reservation and paid dispatch. Estimates with people charges, more credits than requested records, or costs above the configured allocation are rejected before payment. Unexpected paid results remain held for reconciliation; they are never automatically replayed.

The existing owner account response now reports a separately checked discovery readiness and planning-page quote. Start discovery uses the existing authenticated Run endpoint and owner control RPC. It can be offered before outreach campaign release. Readiness checks current ownership, licensed-use expiry as configured, one configured ZIP/state for property-only research (contract-template coverage still gates full-work acquisition), enabled rates, paid funding, wallet availability, rolling daily usage and reservations, and the scoped lifetime spending cap. This read is advisory; existing atomic reservation and claim RPCs still enforce financial and pause controls at dispatch.

Property-only research can run in the configured Tennessee market even when purchase/assignment templates are unavailable there. Missing or ambiguous ZIP/state configuration is held. This does not provision contract templates or change any contract/signing execution check.

The reservation exception is restricted to the actual configured `property_search` rate and exact account/revision/page operation key. It cannot admit owner enrichment, voice, buyer discovery, contracts or other operation types. No rates, wallet amounts, limits, campaign releases, permissions, credentials or live flags are changed by this release.

Owner enrichment remains held under its existing full-work gate because the implemented enriched-property GET has no documented provider quantity cap. Discovery saves real owned screening jobs; it does not create deal terms or recipient consent. The existing draft-save workflow is the manual deal bridge. SMS release/recipient checks, text AI, call invitations and incoming/outgoing voice retain their own holds.

At the inspected production configuration, the five-record page has an existing $0.84 customer planning quote covering ten vendor credits plus allocated overhead/buffer. The configured $0.01/vendor-credit allocation is an operator planning assumption, not a verified invoice price. Successful provider observations remain separate from this quote. These numbers are displayed from current server-owned configuration, not hard-coded in the UI.

Validation: Node route/service tests cover isolated discovery/SMS/full-work combinations, actual Run/account/automation routes, owner/rate/right/coverage/budget failures and sibling holds. The optional low-memory PostgreSQL test invokes actual funding, reserve/claim, scheduling, discovery persistence and screening worker code with intercepted synthetic provider responses, including wallet/day/lifetime rejection, five-record persistence and ambiguous-request no-replay. These tests make no real provider purchase or customer contact.
